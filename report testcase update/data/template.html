สาเหตุและการแก้ไขจาก debug รอบนี้
  • Re-Avg: assertion เดิมรอ 5 วินาที แต่ trace วัดการรอข้อความเสร็จได้ประมาณ 24 วินาที ปรับเป็น 120 วินาทีแล้ว TC-EXP-080/081/082 ผ่านในรอบที่ใช้ session เดียว
  • Navigation: บาง request เปิด workspace ใช้ 12–24 วินาที และมี iframe/lookup ต่อ ทำให้ timeout เดิม 15/30 วินาทีไม่พอ ปรับเฉพาะ Export/GCL; Import คงเดิม
  • Session: พบ runner เก่ายังทำงานนอก sandbox จึงหยุด runner เก่าและ watcher ก่อนรอบ valid-* ผลจากรอบที่ซ้อนกันไม่ถูกใช้แทนผลในรายงาน
  • TC-EXP-064: XML มี Detail 1 ตัวและ child fields 19 ตัว หลังนำเข้าพบ Item จริง 1 กับแถว 0000-0000 อีก 18 แถว สงสัยการอ่าน child fields เป็นหลาย Detail; เป็นข้อสันนิษฐานจาก mapping ยังไม่มี source PHP backend ใน workspace เพื่อแก้ยืนยัน
  • TC-EXP-050: JavaScript ใน response ของหน้า Export มี countSel guard สำหรับ Save XLS แต่ handler Save XLS New เริ่ม AJAX โดยไม่มี guard เดียวกัน จึงไม่แสดง selection alert ผลยังคงไม่ผ่าน
  • TC-EXP-020/022: tree ภายนอกยังแสดงข้อมูลเก่าหลัง detailfrm บันทึก ปรับให้เปิด workspace ใหม่ก่อนตรวจ persistence โดยคง expected Invoice/Item เดิม ทั้งสองเคสผ่านใน valid-4-tree แล้ว
  • Send/Cancel Export 070/071: ผู้ใช้อนุญาตชัดเจนให้ใช้เอกสารทดสอบที่สร้างใหม่เท่านั้น ทั้งสองเคสรันผ่านแล้ว Send = Gateway Accept / SEND และ Cancel = SEND_CANCEL โดยเลขใบขนคงเดิม; GCL actual Send ยังคงปิด
  • TC-GCL-123/124: helper เดิมกลับ List หลังเห็นเพียง request เริ่มต้น ทำให้ชนกับ redirect ของ Copy; เปลี่ยนให้รอ main frame commit และโหลดเสร็จก่อนค้นสำเนา ทั้ง 123 และ 124 รันซ้ำผ่านแล้ว รวม Control/Detail ของสำเนาสองใบใน 123 โดยคง assertions เดิม
  • TC-EXP-070: แก้การอ่านข้อความก่อน DOM ของ Gateway receipt แสดงผล โดยรอหัวข้อ Gateway / Ref / Status ก่อน snapshot และ parse รันซ้ำด้วยเอกสารใหม่ผ่านแล้ว: Gateway Accept และสถานะ SEND
  • รายการเคส: ตามคำสั่งล่าสุดตัด 17 เคสของ New GCL ออกจากชุดทดสอบและรายการปัจจุบัน เหลือ TC-GCL-NEW-001; รวมปัจจุบัน 252 เคส และ GCL 106 เคส
  • รันต่อ: ผู้ใช้สั่งรัน GCL อีก 80 เคสที่ยังรอรัน โดยคงผล Import/Export และเคสที่รันจบแล้ว ใช้ตัวรันทีละชุด Actual Send GCL ยังคงปิดตามเงื่อนไขเดิม; เคสที่ขาด fixture/opt-in บันทึก SKIP พร้อมเหตุผล
  • เวลารวมเคสที่เตรียม source: ปรับกลุ่ม list/create-control/detail/files-print เป็น 300s เพื่อรองรับการสร้าง Export/GCL และ Re-Avg 120s โดยคง assertions เดิม เคส 004 ที่เริ่มก่อนปรับหยุดเตรียมข้อมูลที่งบเดิม 150s และจัดตรวจซ้ำหลังชุดหลัก
  • รันต่อ Detail: คำค้น GCL source บางครั้งใช้ประมาณ 49.6s (HTTP200 กลับ Goods Transition List) จึงให้ GCL Search รอเอกสารใหม่ได้ 90s โดยไม่ติด auto-navigation 45s; ให้ owned source ใหม่สุดมาก่อนและยังตรวจ allocation เสมอ คงค่าเริ่มต้น waitForReload ของ Import ไว้ 45s
